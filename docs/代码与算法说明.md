# 代码与算法说明

更新：2026-11-02。硬件约束已确认：Linux、单 RTX 3090 24GB、零 API 费用。此源码是可运行的机制验证版本；视觉操作主实验按研究计划后续开展。

## 实际执行链

`collect → pairs.npz → train → query.npz/arrival.npz/training.json → evaluate → episodes.csv/traces.jsonl → report`

| 文件 | 职责 |
|---|---|
| `src/advice_audit/envs.py` | ToyReach 与 FetchReach，状态快照、恢复、独立clone、绝对步数目标变化 |
| `src/advice_audit/policies.py` | 反馈P控制器、基于旧观测与名义动力学生成的开环建议 |
| `src/advice_audit/counterfactual.py` | 请求时固定动作块，等待时继续本地控制，到达后成对标签 |
| `src/advice_audit/features.py` | 仅由可见obs/age/plan构造特征 |
| `src/advice_audit/model.py` | 随机特征岭回归ensemble、episode分组训练/校准/测试、序列化 |
| `src/advice_audit/calibration.py` | 按episode最大过估计残差校准一侧下界 |
| `src/advice_audit/evaluation.py` | pending request与动作队列，预算、延迟释放、查询与采纳门控 |
| `src/advice_audit/report.py` | paired bootstrap、汇总与图像 |
| `scripts/sweep.py` | 五训练种子和ID/OOD诊断扫参，串行运行 |
| `scripts/aggregate_seeds.py` | 在固定任务设置内交叉重采样训练seed与环境seed |

## 输入与控制

观测为12维 `[gripper_xyz, achieved_xyz, goal_xyz, observed_goal_velocity_xyz]`。对Reach任务，gripper和achieved重复，是接口为后续操纵适配保留的字段。当前没有RGB、语言编码或LLM推理。目标变化时的velocity只反映已经发生的变化，不包含未来目标。

`local_action()` 用增益6的闭环P控制器。`expert_plan()` 用增益12与近似动力学从请求时观测计算12步建议。专家不知道未来目标，初始速度近似为零。它可能更快也可能更差。两个控制器都不是训练模型，不应称为学习到的VLA。

MuJoCo FetchReach 使用四维原生action的前三维，第四维夹爪指令为0。目标变化及奖励已包装为诊断任务；固定80/120步结束，终点前连续5步到达目标才算成功。报告的是本包装器的成功标准。

## 标签及时间

请求时保存观测并生成候选；每个指定延迟d都从相同请求快照出发，执行d步本地策略。到达状态分叉两个实例，一个执行候选动作块后继续本地策略，一个全程本地策略。两分支同样运行H步或至episode剩余截止时刻。

当前效用：`mean(-goal_distance) + final_hold_success`。标签：`U_accept-U_continue`。它混合米制距离与无量纲成功，是诊断用标量；不是经济成本。每回合净效用再减`cost * requests`，cost单位为此自定义效用单位。H步末成功与整回合末成功不同，论文必须评估短视偏差。

快照只用于离线标签与可选审计。`evaluate --audit`在做出决策后测量标签，不能改决策；会增加host runtime，不应用这些运行时间估算部署性能。

模拟器确实在等待中step；候选本身预计算、按时间释放。不是GPU并发推理、不是云端API调用。用于检验给定延迟下的逻辑。正式实验应加入实测时延trace以及真实并发服务。

## 学习与校准

新增研究路径见 [测量协议v2](MEASUREMENT_PROTOCOL.md)：`collect --audit-deadline` 同时保存短窗口和原episode截止标签；`train --split-manifest ... --target gain_deadline` 使用冻结四路分组（validation与calibration独立），并支持线性ridge/去age/去候选/仅当前状态消融。下文三路描述仍适用于默认bootstrap兼容路径；不要将两套结果混用。
当前随机特征回归器为64个tanh随机特征 + 原始归一化特征 + 截距，5个bootstrap成员；只训练线性输出权重。默认CPU即可训练。ensemble标准差仅是经验不确定性proxy，不是概率保证。

原型按episode分为60% train、20% calibration（代码字段名保留`validation`）、20% offline test。beta=0.5事前固定，没有在calibration标签上选择beta。正式实验需要额外独立validation用于baseline和超参数选择，见实验协议的四路切分。

Arrival target是成对增益。Query target是`max(gain,0)`：假设未来采纳器能够完美拒绝有害建议时的乐观价值代理。它不是联合调度的准确价值函数；不要把辅助query模块作为论文核心。到达时只比较后续增益，已付query cost不再扣。

保形校准使用每episode的最大 `(mean-beta*std-gain)` 残差，取有限样本修正分位数。校准group太少则offset在JSON中为null，数学含义为+∞，门控全部拒绝。代码同时报告offline episode coverage；并不保证一次小样本实验一定达到名义覆盖。

审计文档给出可扩展的标准化残差版本；**当前代码采用不标准化残差与固定ensemble项**。时延网格曲线是离散估计，未实现连续时间覆盖、有效集合预测网络或自适应闭环保证。

## 基线及公正比较

12种配置是工程诊断基线：local/always/periodic/random/risk/ttl/drift/query_only/veto_only/veto_calibrated/advice_audit/advice_audit_calibrated。
`risk`实际是目标距离阈值，不是学习失败概率。`ttl`是手设6步丢弃。原型未实现最近论文的完整算法。不会把它们命名为RTC、REMAC、ForkCast或RESCUE。

默认模式只有共同最大请求上限，不保证相同实际查询数；拒绝可能提前释放查询槽位。已实现 `--fixed-schedule --period 36` 固定槽位模式，要求period >= delay+chunk。对always/ttl/drift/veto_only/veto_calibrated固定查询时刻与次数，隔离不同采纳规则；闭环状态与后续建议仍可因历史采纳而不同。更严格的同候选评测需在相同离线候选集合进行。正式论文仍需调参和真实策略基线。

训练仅采local-only轨迹，因此闭环采纳后状态分布会变化。方法收益、不确定性与coverage须重新测量，不能继承离线分布保证。

## 如何迁移至视觉主实验

1. 新环境适配器需要实现observe/step/snapshot/restore/clone/close，保存物理、任务、随机流及策略队列。先通过重演测试，再采集数据。
2. 用冻结视觉BC或适配目标benchmark的小VLA替换local；使用不同checkpoint/本地规划器作为独立专家。保留模型revision、权重哈希、观测预处理。
3. 视觉轨道gate输入只取图像、本体感知、候选与历史。仿真物体真值只用于离线标注。冻结视觉特征后缓存，小MLP头分阶段训练，不需要把两个大模型同时驻留3090。
4. 恢复状态不仅是env，必须连同RNN/Transformer历史及动作buffer恢复。当前脚本策略无隐状态，因此原型无需该层。
5. 固定请求时间表与状态漂移阈值已实现；进一步加入视觉漂移、学习风险gate、无age/无候选消融、counterfactual oracle；预算统一并只用validation调参。
6. 采集至少1000次真实batch=1推理时间，分开存P50/P95、显存和网络/渲染开销。以trace模拟和真实同卡竞争分别测试。

这里没有预先生成的实验优胜结论。若简单阈值或local-only已足够，就应停止扩大模型，按研究计划做否证。
