# Delayed Advice Audit：机器人应该执行迟到的建议吗？

研究计划 v1.0 · 调研截止 2026-11-01 · 条件：单张 RTX 3090 24 GB、无真机、默认不使用付费 API。

**建议题目：Should a Robot Obey Advice That Arrives Late? Counterfactual Acceptance of Delayed Interventions**

中文：**面向异步机器人智能体的延迟建议采纳：基于反事实收益的时效性判断**。

Delayed Advice Audit（Delay-Aware Counterfactual Intervention）是本项目工作名。这里交付的是研究计划与可运行起步源码，不是已经验证的顶会算法。最终是否值得投稿，取决于下述否证实验与视觉控制主实验，而不能由题目或 demo 判断。

## 1. 研究问题与适合你的原因

快策略在执行，慢专家根据过去的观测生成建议。建议到达时，物体、机械臂或任务目标可能已经变化。即便专家在请求时判断正确，机器人也可能因为机械地执行它而表现更差。

本项目只聚焦一个问题：**给定一条已经到达的具体建议，执行它相对于继续当前快策略，是否仍有正收益？**

例如，专家根据过去画面给出了“朝左移动并抓取”的动作块；在其计算期间，快策略已经完成接近，或目标已经移动。建议到达后，最优动作可能是丢弃建议并继续执行。需要预测的是这条建议在当前状态下的增益，而不是仅预测“机器人是否可能失败”。

这个问题适合单卡资源：冻结快策略与专家，只训练小型收益预测器；反事实标签通过仿真分叉获得，不需要购买机器人或全量训练大模型。3090 用于冻结视觉编码器/小策略推理和小网络训练，CPU 用于模拟与日志。GPU 本身不是唯一瓶颈，仿真、渲染与重复分叉可能更耗时。

## 3. 方法设计

### 3.1 两个时刻，两个不同问题

记请求时刻为 q，到达时刻为 r=q+d，快策略为 π_f，慢专家为 M。专家只能看到请求前历史 h_q，生成具体建议 z=M(h_q)。在 [q,r) 内，机器人继续执行 π_f，环境持续演化。

到达时刻的采纳器输入为 x_r=(h_q,h_r,z,d)，且只能使用部署时可观测的信息。它回答是否接受 z。查询器回答是否值得在 q 时刻付出查询费用；查询器只是辅助模块，论文主贡献应首先在**相同请求时间表**下得到验证。

**已支付的查询成本是沉没成本。**到达后是否接受，比较执行 z 与继续 π_f 的未来收益，不能再次扣除同一笔查询费用。系统总成本报告时，每次实际请求计费一次，包括后来被拒绝或超时的请求。

### 3.2 仿真配对标签

在 r 时刻保存完整快照，包括物理状态、快策略隐状态与动作队列、仿真时钟、目标状态、随机数状态及扰动日程。

从同一快照运行两条分支：

1. **Continue**：继续 π_f；
2. **Accept**：执行建议 z 的约定动作段，然后回到同一 π_f。

两条分支使用相同的未来外生扰动随机数和同样的评价窗口 H。不得让 Accept 多运行若干步或看到更多观测。H 必须足以反映干预后果；同时评估短视标签与完整 episode 结果的差异。

定义相同效用函数 U 后，标签为：

```text
Δ(x_r, z, d) = U(Accept | snapshot_r, common_future)
              - U(Continue | snapshot_r, common_future)
```

训练 fθ(x_r,z,d) 预测 Δ。最简单的回归器作为起点；视觉主实验采用冻结图像编码器加小型 MLP/时序头，不修改主策略权重。必须保留线性/岭回归模型作为同特征基线，证明复杂模型是否必要。

效用需先于主实验冻结。论文主指标以完整任务成功、失败和实际时间分别报告；训练可用任务进度的稠密标签，但不能将进度提升写成成功率提升。若合成为净效用，给出权重、单位及敏感性曲线。

### 3.3 时效性图谱，而非假设“越迟越坏”

对同一请求状态与固定建议 z，考察多个 d，得到条件增益曲线 Δ(d)。延迟可能让建议从有益变有害，也可能在某些阶段保持有效或暂时失效后恢复，因此默认不施加单调性。

定义建议的有效延迟集合：

```text
Vε(hq, z) = {d : E[Δ(hq, hr(d), z, d)] > ε}
```

这是 conditional validity set；只有在数据与理论支持连续性/单调性时才简化为单个“有效截止时间”。论文应报告这种曲线在不同任务阶段、扰动强度和专家来源下的变化，以及模型能否从训练延迟外推到未见延迟。任何线上决策都不能直接读取真实曲线或未来状态。

### 3.4 保守采纳与校准边界

可在独立校准集上，对每个 episode 内预先规定的检查点，计算最大过估计残差：

```text
Ri = max_j [ fθ(xij) - Δij ]
k  = ceil((n_cal + 1) * (1 - α))
qα = 第 k 个校准残差；若 k > n_cal，取 +∞
L(x) = fθ(x) - qα
accept 当且仅当 L(x) > ε
```

这是一种按 episode 分组的一侧 split-conformal 下界。其有限样本覆盖解释要求：模型已固定，校准 episode 与新 episode 交换性成立，检查点生成协议相同。它最多支持这一离线协议下新 episode 预设检查点的联合覆盖陈述。

**不能据此宣称**：分布外延迟仍受保证、逐状态条件覆盖、任意在线自适应策略安全、长期碰撞概率受控、真实机器人安全。采纳动作会改变后续状态分布，离线校准保证一般不会自动迁移到闭环策略。必须在闭环中实测失覆盖率并单独报告；若需要理论贡献，应进一步研究 policy-induced distribution shift，而不是扩大已有结论。

### 3.5 预期论文贡献，均须实验后兑现

1. 将“计算中的建议”与“到达后的建议”区分，提供连续环境中的、针对具体候选的时效性评测协议。
2. 一个小型可训练采纳器，在固定查询预算下预测陈旧建议的反事实增益；展示延迟与当前状态变化特征的独立作用。
3. 对未见延迟、任务及快策略质量的系统分析，包含不起作用和有害的场景；若校准有效，给出边界明确的离线覆盖结果。

“使用反事实”“加入时间特征”“有两个 gate”本身都不构成足够的新颖性。

## 4. 实验层级与单卡实施

| 层级 | 用途 | 接受的输入/策略 | 证据地位 |
|---|---|---|---|
| A：随包 toy + FetchReach 状态轨道 | 验证时钟、快照、数据切分、收益标签与门控代码 | 状态向量、脚本快策略、脚本专家动作块 | 工程诊断，不能支持通用 VLA 或顶会结论 |
| B：视觉 manipulation 主轨道 | 在真实图像观测下检验论文假设 | 冻结 BC/小 VLA + 独立专家；共享视觉输入约束 | 论文必须完成 |
| C：第二任务族/环境与 OOD | 验证不是单一目标漂移或单一脚本优势 | 新任务、对象/布局、扰动与时延分布 | 论文必须完成 |

推荐先完成一个可下载、可运行的 LIBERO 或 ManiSkill 视觉基线，再选其适配成本较低者为主环境；第二环境优先选择已有动态扰动与可靠快照接口者。至少覆盖两类操纵任务，如抓放与推移/抽屉/长序列。若只做到 reach，题目应收缩到控制诊断，不应写“通用机器人智能体”。

主策略优先使用已验证的小模型或 frozen BC checkpoint。LeRobot 官方异步文档给出 SmolVLA 约 2 GB 推理显存这一参考值，但实际峰值受图像数量、序列长度和缓存影响；必须在你的 3090 上重测，不把此值作为显存保证。[官方文档](https://huggingface.co/docs/lerobot/async)

专家可以是：更强 frozen checkpoint、短视野仿真规划器，或只读取视觉/本体感知的小模型。脚本/特权规划器用于上界诊断时必须标注。至少包含一个与训练标签生成器不同的专家，以排除 gate 只学会一个脚本的错误模式。全量大模型训练与高成本 API 不在默认方案内。

建议 Linux、至少 32 GB 内存，64 GB 更舒适，约 100–200 GB 可用 SSD；这些是工程建议，尚未核实用户服务器配置。先以单环境、单图像流启动，仿真并行数由 RAM 与渲染显存实测决定。

## 5. 计算预算：先测量，再扩大

以下为规划额度，不是已测运行时间。

| 阶段 | 预算规划 | 降本方式 |
|---|---|---|
| 环境/模型 profiling | 0.5–2 天人工时间；每个模型记录至少 1,000 次推理 | 冻结版本、批量 1、记录冷启动/稳态、P50/P95 |
| 状态诊断与数据验证 | 1–3 天；CPU 主导 | 小规模分叉，不保存每步 RGB |
| 视觉表征与分叉标签 | 约 40–100 GPU 小时起步额度 | 缓存冻结表征；只在选定检查点分叉；分叉顺序执行 |
| gate 训练、5 个随机种子 | 约 5–20 GPU 小时起步额度 | 只训小头；不得同时反向传播主 VLA |
| 主评测与消融 | 约 80–180 GPU 小时预留 | 先完成筛选，锁定协议后一次执行主要矩阵 |

首版总额暂按 **125–300 GPU 小时**规划，实际可能明显超出。若每次评测太慢，先减少非核心组合，不减少随机种子后继续声称稳健。用公式报告预算：分叉状态数 × 延迟数 × 2 分支 × H 步 / 实测有效步率，再加主策略推理、渲染与 IO。24 GB 显存无法保证任意 VLA checkpoint 可直接运行。

## 7. 投稿定位与最低证据门槛

**首选 CoRL 风格的方法论文**：问题属于机器人学习与策略执行；需要强视觉基线、多任务/多策略和详细开源评测。**RSS** 可以考虑，但单纯工程门控加小仿真通常证据不足，应有更清晰的机制或理论。**ICLR/NeurIPS** 只有在方法可推广为异步决策、覆盖校准或学习增强控制问题，并具备足够广的实验与理论时考虑。这里不列未经核实的征稿日期。

纯仿真可以构成有价值研究，但缺乏真机验证会缩小部署结论。顶刊如 T-RO/IJRR 往往需要更完整的系统论证、实验深度与长期积累；不要把第一版状态原型直接定位为顶刊完成稿。没有真机的默认路径仍是完成可复现的仿真方法研究，而不是为了投稿而购买设备。

建议投稿前至少满足：

- 一条明确且未被最近工作覆盖的新增论点，和对应否证/机制实验；
- 两种任务家族、两个执行环境或一个足够广且含独立动态 suite 的 benchmark；
- 视觉观测主结果，状态 oracle 只作上界；两种专家/策略搭配；
- 同预算下优于固定 TTL、观测漂移、风险 gate 与候选价值 gate，包含既有方法的适配对照；
- 5 个训练 seed，按 episode/task 分组的区间估计，测试集一次锁定；
- 对时延和扰动的 OOD 曲线、失败率与有害采纳率，以及完整 wall-clock 成本；
- 结果不足时明确结论缩小，不声称通用智能、现实安全或已实现真机迁移。

## 8. 负结果与转向

1. **TTL/漂移阈值已足够**：转向“何时复杂慢模块无益”的测量研究，提供时效性图谱、成本分析和完整基线。
2. **专家总体弱于快策略**：先审计干预通道和动作约定；不能通过削弱快策略抬高收益。若专家没有可恢复正收益状态，停止 gate 研究。
3. **仅仿真状态特征有效，视觉无效**：说明观测受限是关键瓶颈；题目改为部分可观测建议有效性估计，补充表征与不确定性分析。
4. **离线校准有效，闭环失效**：把分布偏移作为实证结果；若研究时间允许，再做 policy-specific recalibration。不能修饰为保证成立。
5. **收益来自目标突然变更的人工设置**：加入自然接触/目标运动/策略自己取得进展的场景；若不能复现，缩小适用范围。

## 9. 当前交付与未来工作的界线

随包代码服务于状态诊断轨道：异步逻辑时钟、仿真分叉、数据采集、收益学习、基线与评测，具体可用命令及已测结果以 README 和验证记录为准。**视觉 VLA 主实验、LIBERO/ManiSkill 适配、第二环境、完整多种子结果以及论文录用均不属于已经完成的成果。**

研究计划是一个可执行且可被否证的假设；取得足够证据后再决定论文主张与投稿层级。
