# 实验支持什么，以及应怎样增加研究贡献

日期：2026-11-02。用户要求判断现有观点与发表贡献；创新不足时应增加实质研究，不能把普通技术重新命名。

## 现有证据的结论

**现有证据支持一个有范围限制的负结果，不支持DACI已是有效的新算法。**

1. 对当前状态reach任务、手写local与开环建议器，同一建议可能因到达时间不同而改变收益符号。它证明有时效性现象，不证明学习门控必要。
2. 在原截止指标、匹配请求与强制全拒绝对照下，现有收益回归/校准门控没有跨后端、场景和延迟的一致优势。MAE、coverage或接受率的单个改善不能代替闭环收益。
3. 采集检查点与任务截止影响测到的风险。Toy晚期对齐采集发现early池漏掉的5个末5步hold失败；案例是截止规则内失败，不是碰撞或现实安全事件。
4. 高coverage可能对应近乎全拒绝，且不控制被接受建议中的有害比例。加时钟也没有稳定提升。不能把这些工具写成新的安全保证。

不能推出：复杂门控普遍无用、视觉VLA无效、所有专家建议都无益、conformal理论失效，或当前方法已达到任何投稿录用要求。

## 当前论文贡献为什么仍偏薄

现有可争取的贡献是固定建议的到达干预测量、时窗/截止/成本分离，以及检查点/时钟因子审计。已有实现和可复查结果，但两个后端同属reach、建议源单一且弱、没有视觉或真实延迟，也没有证明建议内容本身存在可提取的额外价值。

把实验数量增加、换网络、加时钟、加conformal、选择执行长度，本身均不是足够的新颖性。若只基于现有材料，适合写范围明确的技术报告/测量草稿；尚不足以负责任地包装成有竞争力的方法论文。

## 新颖性审计修正

此前审计未覆盖下列重要近邻，现补查一手摘要与相关HTML方法结构，并收缩主张：

- [DEFLECT v3，2026-10-20](https://arxiv.org/html/2605.19294v3)：已经用预测时与执行时的时间反事实形成离线偏好监督。因此不能以“时间反事实+延迟建议”这一宽泛组合声称新颖。
- [FutureRTC，2026-07](https://arxiv.org/html/2607.24008v1)：已针对执行时上下文设计状态/视觉预测校正。简单加状态校正不够。
- [Adaptive Q-Chunking，2026-05](https://arxiv.org/abs/2605.05544)：已有按不同执行长度的相对价值选择。不能把critic选块长当新贡献。
- [ChunkTrust v2，2026-10-10](https://arxiv.org/abs/2609.39754)：已有冻结基础策略下的执行长度选择。前缀缩短只能先作强对照。
- [RTC](https://arxiv.org/abs/2506.07339)：已有异步动作块处理。当前简单suffix/反馈跟踪不是完整RTC或FutureRTC复现。

这些工作与已有When to Ask for Help、RESCUE、ForkCast共同限制候选空间。检索仍非穷尽，不以摘要中未提到某对照来证明对方绝对没有。

## 增加的研究问题：补偿后的专家来源价值

工作标题候选：**When Does Late Advice Still Add Information? Separating Execution Repair from Expert-Specific Value**。

现在不仅比较“采纳/拒绝原建议”，而是分开三个量：

1. 原样执行相对继续local的收益；
2. 不额外调用专家，修复已返回建议能够恢复的收益；
3. 在同样修复器下，相对一个廉价local来源，专家内容是否仍提供增量。

固定到达状态x与未来扰动，来源s生成请求时动作z_s，修复器r在到达后处理；定义单次截止增益 `G(s,r)=U(r(z_s))-U(local)`。本轮s为原专家及local的名义模型展开，r为reject/raw/prefix3/suffix/track。

三个可操作的审计对象：

```text
raw option value = max(0, G(expert, raw))
repaired option value = max_r G(expert, r), including reject
source-specific repaired difference = max_r G(expert,r) - max_r G(local_nominal,r)
```

另在validation选定固定r后，在独立test计算同一个修复算子下的来源差，以及相对validation选定的最强廉价固定控制的差。它检验修复是否只重新实现了本地控制。

这些是相对指定来源与修复族的操作性反事实比较，**不是信息论互信息、普遍因果效应、新控制定理，也不是可部署oracle**。修复族最大值读取真实分支标签，只用于评估是否还有学习机会；不能把其提升写成模型效果。

新增贡献候选是“对执行修复和专家内容的归因式评测”，不是修复算子本身。是否达到论文新颖性，仍取决于与全文近邻的完整对照及更真实任务上的证据。

## 新先行实验（在正式test前冻结）

- 配置：`configs/repair_value_pilot_v1.json`。validation seed70000–70011；独立test71000–71011，每后端各12回合，固定周期24、延迟0/4/12、原horizon80，原任务和local保持不变。
- 同请求、同来源计划跨延迟和修复器共享plan hash；控制分支只算一次，所有treatment共享同到达快照与未来扰动。
- 廉价来源只把原local控制器在请求时观测和相同名义模型中展开，不调用专家。不是已经接入的独立学习专家，不能据此宣称完成了第二策略家族。
- raw/prefix3/suffix/反馈跟踪都是简单强对照，参数在test前固定。反馈增益6沿用原local，不用test调节。
- 先采validation、选择一个固定操作/来源并记录，再开始test。统计按完整episode配对，不能把候选数冒充独立样本。
- 预先约定的启发式机会筛选规则：source-specific oracle差的held-out CI下限大于0、均值至少1e-4，同时oracle相对validation固定控制的剩余机会CI下限大于0。该规则仅筛选研究方向，不证明可学习或可部署。尤其有符号的平均专家oracle减廉价oracle并非任意上下文选择器有效的数学必要条件：专家可能只在部分状态有优势。此处保留原冻结规则和结果，不改test判据；后处理另报告正部portfolio增量。
- 若条件不成立，停止在当前手写通道上增加模型；转向独立、具有可恢复价值的建议源及非reach任务，不能靠削弱local制造正结果。

该pilot完成后补充实际结果；在此之前，不声称已增加了一个成功、可发表的新方法。

## 2026-11-02 更新：已实际实现并检验新增方向

两阶段正式实验均完成：先行修复机会pilot（12 validation/12 test）与全新四池学习研究（60/15/15/30 episode、5模型seed）。后者增加增益12廉价源，并给予cheap-only自身的校准界。不是只增加一个研究名称。

结果不支持新选择器有效。Toy/Fetch点估计full平均单次效用分别为-0.00502086/-0.00204151；full减cheap-only为-0.00155657/-0.00046844，两CI均完全负。校准版本Toy全拒绝，Fetch近全拒绝且绝对收益CI含0。新算法成功的主张应放弃；新研究问题与归因协议继续作为测量贡献候选。

在同一新测试池的事后portfolio审计中，加入专家后的实际未来oracle增量 `E[max(Emax,Cmax)-Cmax]` 为Toy0.000250333、Fetch0.00000206147。Fetch廉价组合已覆盖全部oracle的99.54%，故先行pilot仅对比P6廉价源时的正差不能泛化为不可替代的专家信息。Toy仍有来源机会，但当前估计/选择regret超过它。

完整新结果、口径与可投稿贡献边界见[修复/来源结果](REPAIR_VALUE_RESULTS.md)。后续不在当前test上反复调模型找正值；优先验证独立建议源及非reach任务。
