# Delayed Advice Audit 实验协议与预注册模板

版本 1.0 · 2026-11-01。该协议用于后续论文实验；随包状态原型只覆盖其中一部分。不得将原型输出当作视觉机器人主结果。

## 1. 主要假设与先行否证

**H1：时效性现象。**在环境持续推进时，同一请求产生的同一建议，可能随到达延迟变化从有益变为有害。需控制请求状态、建议内容、未来扰动与评价窗口。

**H2：采纳价值。**在相同请求时间表与专家下，学习具体建议的到达增益，优于仅按年龄 TTL、状态漂移或失败风险决定是否接受。

**H3：可迁移性。**学到的采纳机制可迁移到训练未见的延迟/扰动，且至少在一个未用于拟合 gate 的任务家族或策略搭配上保留收益。

**H4：代价。**在完整任务成功率和查询/推理成本共同考量下，收益仍然存在。若只提高中间进度，必须作为该较弱结论报告。

首两周仅测试 H1 和 H2 的简单版本。没有 H1，或 H2 被一个验证集调过的简单 TTL 完全解释，就不推进大规模方法论文。这里没有预先填入“应该提升多少”的结果；可在 pilot 后依据实际基线方差确定最小有意义效应，并在正式 test 前冻结。

## 2. 样本单位、数据切分与可见信息

一个样本由 `(environment, task_id, episode_seed, checkpoint, request_time, arrival_time, expert_id, plan_id)` 标识。一个 episode 的全部时间点、全部延迟以及全部反事实分支归同一 group。

先固定 manifest，再采样/拟合：建议 train 60%、validation 15%、calibration 15%、test 10%；比例可因数据量调整，但 test 不参与门限、特征、归一化或成本权重选择。按 episode 和任务层次划分，不能把同一轨迹的相邻帧随机分到训练和测试。额外建立任务级、策略级与环境级 OOD manifest。

训练归一化参数只由 train 估计。特征提取器版本固定。阈值、query budget 和效用参数只使用 validation；conformal 残差只使用 calibration。每个训练随机种子独立训练，在共同固定 test episodes 上比较。

允许的到达特征：当前与请求时历史图像/本体感知、已执行动作、候选动作块、建议年龄、部署时测得的计算耗时/队列状态。状态轨道可使用仿真直接提供的位置与目标，但必须显著标注 privileged-state diagnostic。

禁止进入 gate 的信息：未来扰动日程、完整 episode 最终成功、分叉结果、环境隐藏对象真值（视觉轨道）、未到达的专家输出、目标未来轨迹、test 标签。实际干预增益只用于训练标签或评测 oracle。

## 3. 时钟与异步执行语义

必须记录三个不同的量：

| 时间 | 定义 | 用途 |
|---|---|---|
| 模拟物理时间 | MuJoCo/仿真器实际推进的秒数与控制步数 | 任务截止时间、动力学、扰动发生时刻 |
| 专家服务时延 | 从 request observation 到返回候选的耗时 | 决定什么时候候选可被采纳 |
| 实验 wall-clock | 采集/训练/评测消耗的真实时间 | 算力成本、部署吞吐和复现资源 |

Synthetic-delay 轨道可以预先计算候选并延迟释放，但 gate 在到达前不得读取它，环境必须照常推进。该轨道模拟的是给定服务延迟，不能写成“真实 GPU 并发运行”。实际部署轨道应采集本机推理 trace 或用独立进程运行专家，再把实际耗时纳入物理步数；不能在等待时冻结物理环境。

单卡同时执行视觉快策略与慢专家会发生 GPU 竞争。分别报告：独立测量并 replay 的时延分布、同卡真实竞争条件的延迟。两者不可混合绘制成同一曲线而不标注。采用固定服务 trace 时，对同一 paired episode 使用同一 trace 和公共扰动随机数。

默认一次只允许一个 pending request；请求未完成时的重复请求处理必须全方法一致。候选携带 request/arrival 时刻、动作坐标系、有效动作段长度；在任务已终止或 episode 已切换后返回的建议直接丢弃，并计入已发生的请求费用。

快策略动作缓冲、当前模式、专家接管期限和 return-to-fast 规则预先冻结。拒绝建议后执行同一个快策略，不能给 Delayed Advice Audit 额外的补救动作。

## 4. 反事实标签的可重演条件

分叉快照至少保存：qpos、qvel、act/ctrl、mocap 状态、物理时间、任务与目标状态、随机数生成器、扰动日程游标、环境 wrapper/TimeLimit、快策略 RNN/Transformer 历史与动作队列，以及剩余任务预算。

Restore 后，在同一动作序列下应重现相同观测、奖励、终止和任务结果；对浮点差异规定容忍度并测试。不能只保存 qpos/qvel 就认定恢复完整。

同一请求固定建议后，先独立推进到各个到达时刻，再由相同到达快照比较 Accept 与 Continue。外生扰动按绝对物理时刻触发，两条分支拥有相同扰动日程；策略引起的状态差异保留，它们正是干预后果。

两条分支共享：剩余总预算、标签窗口、成功标准、失败处理与随机流。若一条提前成功，另一条仍按相同终止语义评估，不人为延长弱分支。报告短窗口增益与整回合增益的一致性，避免只奖励短期接近却损害最终任务。

对有随机性的专家，固定 plan_id 后比较不同延迟；不同专家采样需要独立标签组，不能把采样差异误当延迟效应。

## 5. 必须比较的基线

第一组固定请求时间表，隔离**是否采纳**：

| 基线 | 作用 | 公平性要求 |
|---|---|---|
| Fast-only / Always reject | 无干预下限；实际无需查询的系统基线 | 系统费用为零；在采纳隔离轨道另报告强制查询但全拒绝的诊断版本 |
| Always accept | 衡量陈旧建议直接执行的影响 | 与 Delayed Advice Audit 完全相同的建议和到达时刻 |
| Fixed TTL | 超过固定年龄拒绝 | TTL 在 validation 扫描，不用随便选一个弱阈值 |
| Observation drift | 请求到到达的状态/视觉漂移阈值 | 与 Delayed Advice Audit 同一可见表征，阈值按同预算调优 |
| Failure-risk gate | 预测继续执行是否失败 | 同训练数据量、同模型容量，校准测试分离 |
| Candidate value without delay | 预测候选收益但不输入年龄/历史变化 | 测试时间信息的必要性，不能把它遗漏 |
| Linear/ridge gain gate | 简单低成本同特征收益模型 | 复杂模型若不胜出，保留简单版本为主方法 |
| Delayed Advice Audit point estimate | 预测收益 > 阈值 | 用于分离均值预测与保守校准的作用 |
| Delayed Advice Audit calibrated | 校准下界 > 阈值 | 同一训练模型；独立校准组 |
| Counterfactual oracle | 用真实反事实标签决定接受 | 只能作为离线上界，不算可部署方法 |

第二组在相同平均请求预算或相同总推理成本下比较**什么时候请求**：周期、随机、风险/停滞触发、已有 VoI 风格触发、Delayed Advice Audit 辅助查询器。主论文先证明第一组，否则第二组收益可能来自不同请求位置而不是采纳方法。

与 RTC/REMAC/FlashVLA 对比时，区分底层动作生成与上层采纳。若模型兼容，展示 Delayed Advice Audit 可叠加于现有异步控制，而不是用“暂停等待”的弱基线充当所有已有方法。最近方法若没有完整公开代码，记录获取日期、不可用部分与复现差异，明确写“reimplementation”，不声称复现了作者结果。

## 6. 延迟、扰动与分布外测试

先按专家预测动作块时长 T_chunk 将 delay 归一化，例如训练 d/T_chunk ∈ {0, 0.25, 0.5, 1.0}，测试未见中间值及 {1.5, 2.0}。这些是起始建议，需结合本机实测速度冻结，不应只设置不可能出现的巨大延迟。

至少包含：固定延迟、随机抖动、长尾延迟或短时拥塞，及一条真实推理 trace。零延迟是必要对照；如果方法只在零延迟有效，就不支持本题。

扰动可包括：目标/物体位移、抓取滑落、视觉遮挡、外部运动以及快策略在等待期间自主取得进展。不能只使用“每次固定第 40 步突然换目标”这一可预测规则。训练与测试的扰动时刻、幅度和种类需分离。

分布外维度按独立矩阵报告：

- delay OOD：训练未见的延迟值和分布；
- task OOD：未见任务或任务组合；
- dynamics OOD：摩擦、质量或物体扰动；
- policy OOD：新的快策略 checkpoint 或不同质量水平；
- expert OOD：不同建议生成器；
- visual OOD：未见布局、对象与相机/光照变化。

每个结论注明覆盖哪种 OOD，不能把“新随机种子”写成新任务泛化。

## 7. 指标与统计

主指标：完整任务成功率；在固定请求/计算预算下相对最强可部署基线的 paired 差值。每个任务单独报告，再给等权宏平均，避免大任务量掩盖小任务族失败。

辅助指标：

| 指标 | 计算与解释 |
|---|---|
| 净收益 | 明确权重与单位的任务效用，减实际发生的一次性查询和执行成本；同时报告未合成的各分量 |
| 有害采纳率 | 接受的候选中真实配对增益 < -ε 的比例；ε 预先冻结，并另报 ε=0 |
| 漏失有益建议率 | 反事实增益 > ε 的候选被拒绝比例；与有害采纳率一起报告，避免“全拒绝”看起来最好 |
| 请求率/接受率 | 每回合请求数、接受数、拒绝数、超时数；费用按请求而非接受次数计算 |
| Regret | 相对同候选集的 counterfactual oracle 的效用差距；oracle 不是现实上限 |
| 校准 | offline episode-level coverage、区间宽度/下界紧度；在线 closed-loop coverage 单独报告 |
| 时间 | 完整回合物理时间、wall-clock、专家调用 P50/P95、gate P50/P95、GPU 峰值显存 |
| 控制质量 | 若任务提供则报告碰撞、jerk、动作切换频率；不将 proxy 当成真实安全保证 |

至少 5 个 gate 训练随机种子；主要条件每个任务至少 50 个固定 test episode 作为起始设计。真实样本量由 pilot 方差与预先声明的效应量决定，不在结果不显著后无限增加。

使用 paired episode seed：所有方法从相同任务初始状态开始，共享外生扰动和时延 trace。计算差值后按 task/episode 分组 bootstrap，保留训练 seed 的层次；绝不能把同一 episode 的上百个候选当独立样本。报告 95% CI、绝对百分点差与样本数。对预注册主要对比之外的多重检验作 Holm 等修正或标注探索性分析。

CI 跨零就如实写证据不足。成功率不劣而查询下降可以是贡献，但必须按事先规定的非劣界做检验；不能事后把“未显著下降”解释成等价。

## 8. Conformal 声明检查表

按 episode 最大过估计残差校准，只在固定数据生成协议与交换性条件下使用对应覆盖结论。train/calibration/test 的划分单位为完整 episode。

每份结果同时回答：

1. 校准与测试 episode 是否由同一固定行为策略/检查点规则生成？
2. 测试策略接受建议后是否改变了后续特征分布？若是，离线保证不自动适用。
3. test 是否有未见延迟、任务、动力学或专家？若是，只能实测 OOD 覆盖。
4. 有多少校准组？分位数索引超出样本数时是否返回无限保守下界？
5. 低有害采纳率是否仅由几乎全部拒绝实现？同时报告收益和接受率。

在没有额外证明前，不写“以 95% 概率确保每次干预安全”或“保证闭环不退化”。

## 9. 日志与复现材料

每次 run 保存：git commit（若使用版本库）、环境/依赖锁定、GPU/驱动/CUDA、CPU/RAM、模型仓库和 revision、checkpoint checksum、配置与 seed、任务 manifest、异常/失败计数、每回合结果、每次请求/到达/采纳事件与 trace。

建议事件字段：

```text
run_id, policy_seed, episode_id, task_id, env_seed,
sim_step, sim_seconds, wall_seconds,
request_id, request_step, arrival_step, plan_id, delay_seconds,
gate_score, calibrated_lower_bound, decision, query_cost,
success, terminated, truncated, failure_reason
```

训练数据另存 snapshot/branch ID、Continue 与 Accept 效用及 Δ，但不要把这些字段传入部署时特征。日志中的真实 oracle 标签与线上预测列应命名分离。

发布时包含：运行命令、依赖、数据 manifest、关键 checkpoint 或生成方式、训练 seed、逐回合 CSV/JSONL、配对统计脚本、失败视频、耗时/显存表。没有完成的实验用 `not_run`，不能用零或预期值填充。

## 10. 论文表图清单

1. 系统图：请求、快策略继续执行、建议到达、采纳/拒绝的时间线。
2. 同建议、不同延迟的 Δ(d) 曲线，含正负翻转与非单调反例。
3. 固定查询时间表下的成功率—有害采纳率—成本前沿。
4. 与最强简单阈值及候选价值基线的任务级 paired 差值和 95% CI。
5. delay/task/expert OOD 矩阵，干净与扰动场景都保留。
6. 去除年龄、候选、当前历史、校准及配对标签后的消融。
7. 离线与闭环校准覆盖并列图，明确保证与实测的区别。
8. 完整失败案例与实时速度视频；加速视频显著标注倍率。
